三、Phase 12-1：Solution legacy requirement 清理
============================================================

目标：

彻底降低 Solution 对旧 requirement 结构的依赖。

当前问题：

RequirementProfile
        ↓
profile_to_solution_requirement()
        ↓
legacy requirement
        ↓
Solution

同时 Solution 仍然存在：

profile
requirement
history


----------------------------
步骤 1：统计真实使用情况
----------------------------

全仓库搜索：

- requirement
- requirements
- requirement_profile
- profile_to_solution_requirement
- SolutionState
- history requirement extraction

建立引用表：

文件
↓
读取字段
↓
是否参与决策
↓
是否仅兼容
↓
是否可以删除


----------------------------
步骤 2：明确唯一真实来源
----------------------------

正式规定：

RequirementProfile = 唯一业务需求来源

Solution 不允许重新建立自己的需求模型。

正常链路：

Sales / Turn
      ↓
RequirementProfile
      ↓
Solution


----------------------------
步骤 3：legacy requirement 改为只读兼容
----------------------------

如果暂时不能删除：

保留：

solution_state["requirement"]

但是规定：

只能：

读取
转换
兼容旧接口

不能：

修改
重新推导
重新抽取
参与新的需求决策


----------------------------
步骤 4：关闭 history → requirement 重新抽取
----------------------------

当前如果存在：

Solution
 ↓
发现 profile 不存在
 ↓
读取 history
 ↓
重新提取 requirement

逐步取消。

最终：

如果没有 RequirementProfile：

不要让 Solution 自己重新建立需求。

应该：

返回明确状态：

REQUIREMENT_NOT_READY

再交由上层处理。


----------------------------
步骤 5：删除兼容代码
----------------------------

当以下条件全部满足：

- 所有正常调用都使用 RequirementProfile
- 测试不再依赖旧 requirement
- Solution 不再从 history 重新抽取
- legacy requirement 没有业务写入

才删除：

profile_to_solution_requirement()

以及相关 legacy adapter。

四、Phase 12-2：Dialogue Question 层最终收口
============================================================

目标：

解决：

question_planner
question_flow
question_order
question_registry

职责重复的问题。


----------------------------
最终职责
----------------------------

Question Policy：

只负责：

“下一步最应该问什么？”


QuestionSpec：

只负责：

“这个问题如何被表达？”


ResponseGenerator：

只负责：

“如何自然表达整个回复？”


三者严格分开。


----------------------------
禁止
----------------------------

QuestionPlanner 不得：

- 生成完整回复
- 决定最终 Response
- 决定产品推荐
- 修改 RequirementProfile

ResponseGenerator 不得：

- 重新决定问什么
- 重新选择 question slot
- 重新决定 Recommendation


----------------------------
步骤
----------------------------

1.

检查：

question_planner
question_flow
question_order
question_registry

逐个统计调用方。

2.

如果只是：

A → B → C

纯转发：

合并。

3.

如果某模块保存：

slot 定义
slot 顺序
candidate 规则

提取到唯一 QuestionPolicy。

4.

如果只是历史兼容：

标记 LEGACY。

5.

确认没有业务调用后删除。

      ↓

- 当前业务状态

- 允许使用的事实


----------------------------
ResponseGenerator
----------------------------

只负责：

把已经确定的业务动作表达成自然语言。


不得重新决定：

- 产品类型
- 下一问题

- Gate
- Calculation

ResponseValidator
----------------------------

只负责：

最终检查：

- 是否问错问题
- 是否问了多个问题
- 是否重复已知信息
- 是否出现未确认型号
- 是否出现不存在参数
- 是否与 RequirementProfile 冲突
- 是否出现不完整回复


----------------------------
最终处理
----------------------------

如果：

response_coordinator

只是中间转发：

删除。


如果：

final_response

只是包装：

合并。


如果：

natural_continuation

只是表达辅助：

并入 ResponseGenerator。


如果：

final_guard

和：

response_validator

职责重复：

保留一个最终校验入口。


注意：

必须先跑引用分析。

禁止直接删除。

----------------------------

“最终选择 LED。”

1. 0 个业务调用
2. 0 个测试依赖
3. 0 个运行时 import
4. 新实现已经完全接管
5. 全量测试通过
6. Regression Test 通过
7. 架构 Guard 通过
8. API 行为没有变化


否则：

保留。

============================================================
十六、禁止“顺便优化”
============================================================

执行 Phase 12 时，如果发现：

“这里其实可以优化一下”

不要顺便改。

例如：

不要顺便：

- 修改 prompt
- 修改推荐算法
- 修改问题顺序
- 修改产品类型规则
- 修改模型
- 修改 RAG
- 修改产品数据
- 修改计算公式
- 修改销售话术策略


全部记录到：

docs/plans/future_optimization.md


Phase 12 只做：

架构残留清理。

唯一最终回复校验入口


【Recommendation】

RecommendationGate
→
RecommendationEngine
→
RecommendationValidator


【Solution】

Solution
不再从 history 自己重新构建 Requirement。


【API】

API
不参与业务决策。


【RAG】

RAG
只提供知识，不决定业务 Action。


【Tests】

新功能测试
+
Regression
+
Architecture Guard

三者共同保护系统。

============================================================
二十、最终原则
============================================================

Phase 12 不是：

“继续给项目加功能”。

而是：

“把已经完成的功能真正收口。”

最终要求：

少入口
少状态
少重复
少兼容层
少隐式决策
少历史代码

但是：

核心功能不减少
推荐逻辑不改变
产品逻辑不改变
客户体验不改变
RAG 不改变
计算不改变

一句话：

不改业务，只清理残留；
不重构核心，只消除重复；
不为了代码漂亮而改变系统行为。
